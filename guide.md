# AR Kitchen — Project Guide

AR mobile app (Android/ARCore, iOS/ARKit) that lets kitchen makers visualize a kitchen in a client's space before installation. The user scans the room, places a single cuboid ("voxel") on a detected AR plane to mark the kitchen volume, adjusts its dimensions, and fills it with predefined kitchen elements (fridge, counter, sink, oven…) sized to standard real-world measurements.

Built with Unity 6 (`6000.3.13f1`), URP (Performant preset), AR Foundation 6.3, XR Interaction Toolkit 3.3, and the New Input System. Runtime UI is UI Toolkit (UXML/USS).

## How the app flows

1. **Scanning** — `SurfaceScanFlow` shows the "Scanning your room" panel (`ScanningPanel`) until `ARPlaneManager` reports a detected plane (with a minimum on-screen time so it doesn't flash by).
2. **Surfaces found** — cross-fades to `SurfacesFoundPanel`; the user confirms they want to place the kitchen.
3. **Placement** — `PlaceKitchenPanel` shows a hint; `VoxelPlacer` is enabled and the next tap on an AR plane instantiates the voxel prefab there (one-shot).
4. **Placed HUD** — `PlacedHudPanel` fades in: Voxel/Planes visibility toggles top-right, a "Kitchen space" card and an **Edit** button at the bottom.
5. **Editing** — Edit puts `VoxelStateManager` into editing state; `KitchenEditPanel` takes over the bottom of the screen with five modes: **Scale** (W/D/H sliders), **Placement** (camera-relative move pad + tap-to-replace), **Rotation**, **Fill Kitchen** (element catalog), and **Color** (RGB sliders driving shared materials).
6. **Filling** — in Fill Kitchen mode, elements from the catalog are added to `KitchenLayoutController`, which lines them up along the voxel's wall edge, tracks used/remaining length, and rejects elements that don't fit. Tapping a placed element opens a variant picker that swaps its model without changing the layout.

## Core architecture

Everything hangs off **`VoxelStateManager`** — the central hub. It owns the editing state and the current `VoxelEditMode` (`None / Scale / Placement / Rotation / FillKitchen / Color`) and broadcasts three events that every UI script subscribes to: `OnVoxelPlaced`, `OnEditingChanged`, and `OnModeChanged`. UI scripts never talk to each other directly; they react to state-manager events and call into the voxel/layout controllers.

```
VoxelPlacer ──OnPlaced──▶ VoxelStateManager ──events──▶ all UI panels
                               │
                               ▼ Controller
                         VoxelController ──OnResized──▶ KitchenLayoutController ──OnLayoutChanged──▶ HUD/Edit UI
                                                              │
                                                              ▼ instantiates
                                                        KitchenElementView (per element)
```

## Most important scripts

### Voxel core — `Assets/Scripts/`

| Script | Role |
|---|---|
| `VoxelStateManager.cs` | Central state hub (see above). Also enables/disables `VoxelPlacer` when entering/leaving Placement mode. |
| `VoxelPlacer.cs` | On the XR Origin. AR-raycasts the first tap onto a detected plane and instantiates the voxel prefab. One-shot: after placement, taps are ignored until `AllowReplace()` re-arms it (Placement edit mode). Ignores taps over UI (both uGUI and the UI Toolkit edit panel). |
| `VoxelController.cs` | On the voxel prefab. Holds width/depth/height, rebuilds the visuals on `Resize` (a translucent fill cube plus 12 `Edge_*` wireframe children), and exposes `MoveTo`, `Rotate`, and `SetVisible` (hides marker visuals without hiding placed kitchen elements). Fires `OnResized`. |
| `VoxelMovement.cs` | While in Placement mode, drags the voxel along detected planes by AR-raycasting the touch position each frame. |

### Kitchen layout — `Assets/Scripts/Kitchen/`

| Script | Role |
|---|---|
| `KitchenLayoutController.cs` | Lives on the voxel next to `VoxelController`. Maintains the ordered list of placed elements, lines them up against the voxel's left wall edge from back to front, tracks `UsedLength` / `RemainingLength`, and validates fit (`DepthFits`, `LengthFits`) before `TryAdd`. Repositions everything when the voxel is resized. The positioning math lives in `Reposition()` — read its comment before touching it. |
| `KitchenElementDefinition.cs` | `ScriptableObject` describing one catalog element: name, code, group (Storage/Washing/Cooking), real-world W/H/D in meters, default model prefab plus variant prefabs (same footprint), mandatory/filler flags. Created via *AR Kitchen → Kitchen Element Definition*; assets generated by the editor setup scripts. |
| `KitchenElementView.cs` | Runtime view for one placed element. Instantiates the definition's FBX model, normalizes it so its bounding-box min corner sits on the view origin (so the layout controller can place it without per-model offsets), applies the 180° "face the room" yaw, and adds a `BoxCollider` tap target. `ApplyVariant(i)` swaps the model in place. |

### UI Toolkit panels — `Assets/Scripts/UI/` (current UI)

UXML layouts live in `Assets/UI/Documents/`, styles in `Assets/UI/Styles/`.

| Script | Role |
|---|---|
| `SurfaceScanFlow.cs` | Orchestrates the onboarding sequence (scanning → surfaces found → place hint → placed), wiring plane detection and `VoxelPlacer.OnPlaced` to panel cross-fades. |
| `KitchenEditPanel.cs` | **The biggest script (~820 lines)** — the whole edit experience in one UI Toolkit panel: mode tab bar, size sliders, camera-relative move pad, rotation controls, element catalog with category tabs and fit/mandatory feedback toasts, placed-element strip, variant picker overlay, and RGB color editing of the two shared kitchen materials. Also exposes the static `IsPointerOverBlockingUi()` that `VoxelPlacer`/`VoxelMovement` use to keep AR taps from going through the UI. |
| `PlacedHudPanel.cs` | Post-placement HUD: voxel/plane visibility toggles, kitchen-space summary card (unit count via `KitchenLayoutController.OnLayoutChanged`), Edit button. Hides its bottom bar while editing. |
| `ScanningPanel.cs`, `SurfacesFoundPanel.cs`, `PlaceKitchenPanel.cs` | The three onboarding panels; animations run on UI Toolkit's scheduler. |
| `UIFade.cs` | Shared opacity cross-fade helper for panel roots. |

### Legacy uGUI scripts — `Assets/Scripts/` (superseded)

`KitchenUI`, `VoxelScaleUI`, `VoxelRotationUI`, `VoxelToggleUI`, `PlaneToggleUI`, `MaterialColorUI`, `KitchenCatalogUI`, `ElementVariantUI` are the older Canvas/uGUI versions of the edit flow from before the UI Toolkit migration (commit `7d150b1` "Migrate AR UI to UI Toolkit"). They are still referenced in `MainScene` but their functionality now lives in `KitchenEditPanel` / `PlacedHudPanel`. Prefer the UI Toolkit path for new work; these are candidates for removal.

### Other

| Script | Role |
|---|---|
| `ARPlaneFeather.cs` | Feeds each AR plane's bounds to the custom "AR Kitchen/Feathered Plane" shader (`Assets/Shaders/`) so the dot pattern fades at plane edges. On the `ARPlane` prefab. |

Useful for understanding how the scene is wired, not used at runtime. |

## Key assets

- `Assets/Scenes/MainScene.unity` — the only scene.
- `Assets/Prefabs/Voxel.prefab` — the kitchen volume marker (`VoxelController` + `KitchenLayoutController`).
- `Assets/Prefabs/KitchenElement.prefab` — the per-element view shell (`KitchenElementView`).
- `Assets/Prefabs/Elements/`, `Assets/Models/` — element prefabs and FBX models grouped by Storage / Washing / Cooking.
- `Assets/Materials/KitchenMainMaterial` + secondary — the two shared materials Color mode recolours (every element using them updates at once; editor edits persist to the asset on purpose).
- `Assets/UI/PanelSettings.asset` — UI Toolkit panel settings shared by all UIDocuments.

## Conventions worth knowing

- Coordinate/layout invariants: elements assume the voxel's **left edge (−X) is the wall**; models are authored facing the wall and footprint-normalized by `KitchenElementView`. Variants must share the default model's footprint.
- Task tracking lives in `TODO.md` / `PROBLEMS.md` at the repo root (managed by the `/todo` and `/plan` skills).
- Commits follow `.claude/skills/commit/SKILL.md`: major features on `feat/<name>` branches, imperative subject ≤ 70 chars, bullet list of major work, no prefixes. Stage files by name.
- See `CLAUDE.md` for the full project brief and rules.
